### 📋 HU-07: Autenticación Segura e Inicio de Sesión

**Como** Usuario registrado (Cliente o Administrador) de SneakerHub  
**Quiero** ingresar mis credenciales de acceso (correo electrónico y contraseña)  
**Para** ser autenticado por el sistema, obtener un token digital seguro (JWT) y navegar por las secciones restringidas según mi nivel de privilegios.

---

#### 📌 1. Precondiciones y Postcondiciones
* **Precondiciones:**
  1. El usuario debe haber completado previamente su registro en la plataforma (HU-06) o existir en la base de datos a través de una siembra de datos (*seed*).
  2. La cuenta analizada debe tener un estado válido y activo en el motor de persistencia MySQL.
* **Postcondiciones:**
  1. El backend expide una firma criptográfica de acceso temporal de corto alcance de tipo Bearer.
  2. El cliente frontend captura el token resultante y lo almacena localmente en la memoria dinámica o estado de la aplicación para interceptar las llamadas salientes mediante `api.js`.

---

#### 🛠️ 2. Criterios de Aceptación Técnicos Detallados
* **CA-01 (Mitigación de Enumeración de Cuentas):** Por directivas internacionales de ciberseguridad, ante un fallo en el proceso de autenticación (ya sea porque el correo no existe o porque la contraseña es incorrecta), el sistema **no debe revelar** cuál de los dos campos fue el erróneo. El backend responderá con un mensaje genérico unificado: `"Credenciales inválidas. Verifique su correo o contraseña."` y un código de estado estricto **401 Unauthorized**.
* **CA-02 (Cruce de Verificación de Contraseñas):** El controlador extraerá el `contrasena_hash` asociado al correo desde MySQL. Utilizando la librería `bcrypt`, ejecutará el proceso de verificación síncrona en un hilo seguro aplicando salado dinámico sobre la marcha. Si las firmas no coinciden matemáticamente, la transacción es abortada inmediatamente.
* **CA-03 (Estructuración del Payload de Sesión - Claims JWT):** Al confirmarse la identidad, el método emisor de tokens en `core/security.py` empaquetará las claims dentro del cuerpo del JWT utilizando el algoritmo simétrico **HS256**:
  * `sub` (Subject): Almacena el correo electrónico del usuario.
  * `rol`: Almacena la jerarquía exacta (`"admin"` o `"cliente"`).
  * `exp`: Registra la marca de tiempo exacta de expiración para forzar el cierre de sesión automático tras el ciclo programado.
* **CA-04 (Optimización de Hilos de Lectura):** Al buscar la cuenta de usuario, la consulta SQL debe apuntar directamente a un índice único sobre la columna `email`. Esto reduce la complejidad temporal de la búsqueda a un escenario ideal de tiempo constante $O(1)$, evitando escaneos masivos de tablas en producción.

#### 📊 3. Esquemas de Validación y Contratos de Datos (Pydantic)

```python
from pydantic import BaseModel, Field, EmailStr

# Esquema de Entrada para la solicitud de inicio de sesión
class UsuarioLogin(BaseModel):
    email: EmailStr = Field(..., description="Correo electrónico del usuario registrado")
    password: str = Field(..., min_length=6, description="Contraseña en texto plano a verificar")

# El contrato de salida reutiliza la firma TokenResponse de la HU-06
class TokenResponse(BaseModel):
    access_token: str = Field(..., description="Firma criptográfica JWT generada con éxito")
    token_type: str = Field(default="bearer", description="Esquema de autorización estándar")
```

#### 🗄️ 5. Implementación del Algoritmo del Controlador (FastAPI + SQLAlchemy)

```python
from fastapi import APIRouter, Depends, HTTPException, status
from sqlalchemy.orm import Session
from app.database import get_db
from app.models.user import Usuario
from app.schemas.user import UsuarioLogin, TokenResponse
from app.core.security import verificar_contrasena, crear_token_acceso

router = APIRouter(prefix="/api/auth", tags=["Autenticación"])

@router.post(
    "/login", 
    response_model=TokenResponse,
    status_code=status.HTTP_200_OK,
    summary="Autenticar credenciales y recuperar token JWT de sesión"
)
def iniciar_sesion(
    payload: UsuarioLogin, 
    db: Session = Depends(get_db)
):
    # 1. Buscar al usuario en MySQL optimizado mediante el índice del email
    correo_buscar = payload.email.strip().lower()
    usuario = db.query(Usuario).filter(Usuario.email == correo_buscar).first()
    
    # 2. Control genérico perimetral: Si el usuario no existe, abortar sin dar pistas
    if not usuario:
        raise HTTPException(
            status_code=status.HTTP_401_UNAUTHORIZED,
            detail="Credenciales inválidas. Verifique su correo o contraseña."
        )
        
    # 3. Validar criptográficamente la contraseña utilizando la firma hash guardada
    contrasena_valida = verificar_contrasena(payload.password, usuario.contrasena_hash)
    
    # 4. Si el hash falla, abortar con el mismo mensaje genérico preventivo
    if not contrasena_valida:
        raise HTTPException(
            status_code=status.HTTP_401_UNAUTHORIZED,
            detail="Credenciales inválidas. Verifique su correo o contraseña."
        )
        
    # 5. Emitir el token web JSON con los roles estructurales recuperados de la fila
    claims_sesion = {
        "sub": usuario.email,
        "rol": usuario.rol
    }
    token_emitido = crear_token_acceso(data=claims_sesion)
    
    return TokenResponse(access_token=token_emitido, token_type="bearer")
```
