## 📊 MÓDULO C: TRANSACCIONES, CHECKOUT Y TELEMETRÍA ANALÍTICA

### 📋 HU-13: Subsistema de Telemetría y Reportes de Bajo Stock (Admin)

**Como** Administrador de Operaciones y Almacén de SneakerHub Ayacucho  
**Quiero** consultar un reporte analítico automatizado que filtre los modelos y variantes de calzado cuyo inventario físico se encuentre por debajo de un umbral crítico parametrizable  
**Para** gestionar reabastecimientos preventivos de mercancía con los proveedores y mitigar la pérdida de ventas por quiebre de stock en la plataforma web.

---

#### 📌 1. Precondiciones y Postcondiciones
* **Precondiciones:**
  1. El usuario debe estar autenticado con un token JWT vigente que posea la claim `"rol": "admin"`.
  2. Las tablas de `productos`, `variantes_color` y `tallas_stock` deben estar pobladas e interconectadas en MySQL.
* **Postcondiciones:**
  1. El backend ejecuta un barrido analítico agregando las existencias físicas de las celdas de inventario.
  2. Se devuelve un payload JSON detallado con las métricas de escasez listo para ser consumido por los paneles gráficos del frontend en el módulo de reportes (`reports.py`).

---

#### 🛠️ 2. Criterios de Aceptación Técnicos Detallados
* **CA-01 (Seguridad de Estado y Auditoría):** Al exponer métricas comerciales estratégicas y de inventario logístico, la ruta alojada en `routers/reports.py` está restringida bajo la dependencia `@verificar_admin`. Intentos de acceso sin credenciales válidas o por clientes estándar devuelven un código de error **403 Forbidden**.
* **CA-02 (Parámetro Elástico de Umbral Crítico):** El endpoint interceptará un Query Parameter denominado `umbral`. Este valor debe ser un número entero mayor o igual a cero (`ge=0`). Si el frontend no provee este parámetro, el backend aplicará de forma automática el valor por defecto de **5 unidades**, considerando críticamente cualquier stock menor o igual a dicho umbral.
* **CA-03 (Agregación SQL Atómica y Evitación de Bucles):** Para optimizar la memoria del servidor, está prohibido extraer todos los registros a Python para filtrarlos en bucles `for`. La consulta de SQLAlchemy debe inyectar funciones de agregación y agrupamiento nativo en el motor InnoDB de MySQL utilizando cláusulas equivalentes a `SUM(tallas_stock.stock)` y `GROUP BY`.
* **CA-04 (Complejidad de Datos en Alerta):** El reporte no debe ser plano; cada fila devuelta debe desglosar el ID del producto, el nombre del calzado, el color específico de la variante afectada, la talla exacta que se encuentra en estado crítico y el número exacto de existencias remanentes en almacén.

#### 📊 3. Esquemas de Validación y Contratos de Datos (Pydantic)

```python
from pydantic import BaseModel, Field
from typing import List

# Estructura del ítem de alerta dentro del reporte analítico
class AlertaStockItem(BaseModel):
    producto_id: int = Field(..., description="ID del calzado base")
    producto_nombre: str = Field(..., description="Nombre comercial del calzado")
    color: str = Field(..., description="Variante cromática afectada")
    talla: str = Field(..., description="Talla específica en desabastecimiento")
    stock_remanente: int = Field(..., description="Cantidad de unidades físicas en almacén")

    class Config:
        from_attributes = True

# Contrato de Salida Global (Envelope JSON)
class ReporteBajoStockResponse(BaseModel):
    umbral_aplicado: int = Field(..., description="Línea de corte utilizada para el reporte")
    total_alertas_encontradas: int = Field(..., description="Conteo de celdas que requieren reabastecimiento")
    alertas: List[AlertaStockItem] = Field(..., description="Listado detallado de variantes críticas")
```

#### 🗄️ 5. Implementación del Algoritmo del Controlador (`backend/app/routers/reports.py`)

```python
from fastapi import APIRouter, Depends, Query, status
from sqlalchemy.orm import Session
from app.database import get_db
from app.models.product import Producto
from app.models.variant import VarianteColor, TallaStock
from app.schemas.variant import ReporteBajoStockResponse, AlertaStockItem
from app.routers.auth import verificar_admin

router = APIRouter(prefix="/api/reports", tags=["Reportes Analíticos"])

@router.get(
    "/bajo-stock", 
    response_model=ReporteBajoStockResponse,
    status_code=status.HTTP_200_OK,
    summary="Recuperar telemetría de variantes de calzado con stock crítico (Solo Admin)"
)
def generar_reporte_bajo_stock(
    umbral: int = Query(default=5, ge=0, description="Cantidad límite para activar la alerta de escasez"),
    db: Session = Depends(get_db),
    admin_actual = Depends(verificar_admin)
):
    # 1. Construir consulta relacional uniendo las tres tablas esenciales en un solo viaje
    # Filtra celdas de inventario que tengan stock menor o igual al umbral parametrizado
    query_alertas = db.query(
        Producto.id.label("prod_id"),
        Producto.nombre.label("prod_nombre"),
        VarianteColor.color.label("var_color"),
        TallaStock.talla.label("item_talla"),
        TallaStock.stock.label("item_stock")
    ).join(VarianteColor, Producto.id == VarianteColor.producto_id)\
     .join(TallaStock, VarianteColor.id == TallaStock.variante_color_id)\
     .filter(TallaStock.stock <= umbral)\
     .filter(Producto.estado == "ACTIVO")\
     .order_by(TallaStock.stock.asc())\
     .all()

    # 2. Mapear de forma limpia las filas de la consulta hacia la lista de esquemas de Pydantic
    lista_alertas = []
    for row in query_alertas:
        lista_alertas.append(
            AlertaStockItem(
                producto_id=row.prod_id,
                producto_nombre=row.prod_nombre,
                color=row.var_color,
                talla=row.item_talla,
                stock_remanente=row.item_stock
            )
        )

    # 3. Empaquetar y despachar el sobre-encapsulado analítico final (Envelope)
    return ReporteBajoStockResponse(
        umbral_aplicado=umbral,
        total_alertas_encontradas=len(lista_alertas),
        alertas=lista_alertas
    )
```
