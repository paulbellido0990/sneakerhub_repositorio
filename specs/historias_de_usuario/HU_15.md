### 📋 HU-15: Gestión del Ciclo de Vida del Pedido y Transición de Estados (Admin)

**Como** Administrador de operaciones de SneakerHub Ayacucho  
**Quiero** consultar el listado global de órdenes de compra y mutar el estado logístico de un pedido (de "PENDIENTE_VERIFICACION" a "PROCESADO", "ENVIADO" o "CANCELADO")  
**Para** coordinar el flujo de despacho con los repartidores locales en Huamanga, auditar los pagos recibidos y gestionar la reversión de inventarios en caso de cancelaciones.

---

#### 📌 1. Precondiciones y Postcondiciones
* **Precondiciones:**
  1. El usuario debe estar autenticado con un token JWT vigente bajo la verificación restrictiva de `@verificar_admin`.
  2. Debe existir la orden de compra previamente emitida por un cliente en la tabla `pedidos` (HU-14).
* **Postcondiciones:**
  1. Se actualiza de forma persistente la columna `estado_pago` de la cabecera del pedido en MySQL.
  2. Si el pedido entra en estado `"CANCELADO"`, se ejecuta un algoritmo de restitución física que reinyecta las unidades previamente reservadas de vuelta a sus respectivas celdas en `tallas_stock`.

---

#### 🛠️ 2. Criterios de Aceptación Técnicos Detallados
* **CA-01 (Seguridad Logística de Estados):** La ruta de mutación y consulta global de órdenes de compra está alojada en `routers/orders.py` y blindada bajo el guardián `@verificar_admin`. Clientes estándar o usuarios anónimos que intenten auditar o modificar el estado de un pedido recibirán un código **403 Forbidden**.
* **CA-02 (Validación de Máquina de Estados Estricta):** Para evitar inconsistencias operativas, el campo `nuevo_estado` se someterá a una validación elástica de contención en lista blanca. Solo se autorizan los siguientes literales estrictos:
  * `"PENDIENTE_VERIFICACION"` (Estado base de checkout)
  * `"PROCESADO"` (Pago validado en cuenta bancaria/Yape/Plin)
  * `"ENVIADO"` (Mercancía entregada al repartidor para delivery en Huamanga)
  * `"CANCELADO"` (Orden anulada por el cliente o rechazo de pago)
  Cualquier otro literal será interceptado por Pydantic arrojando un código **422 Unprocessable Entity**.
* **CA-03 (Restitución Atómica de Almacén por Cancelación):** Si el administrador cambia el estado de la orden a `"CANCELADO"`, el backend debe realizar un bucle interno que extraiga todos los registros hijos de `detalles_pedido`. Por cada ítem cancelado, el sistema sumará las unidades de forma síncrona en la tabla `tallas_stock`:

  `TallaStock.stock = TallaStock.stock + DetallePedido.cantidad`

  Este proceso se ejecutará bajo el amparo de un bloque transaccional InnoDB. Ante cualquier fallo físico o corte de red, se invocará `db.rollback()` para evitar duplicaciones o pérdidas fantasmas de inventario.

#### 📊 3. Esquemas de Validación y Contratos de Datos (Pydantic)

```python
from pydantic import BaseModel, Field, field_validator

# Lista blanca inmutable de estados permitidos en el ecosistema
ESTADOS_VALIDOS = ["PENDIENTE_VERIFICACION", "PROCESADO", "ENVIADO", "CANCELADO"]

# Payload de Entrada: Modificación del estado del pedido
class CambiarEstadoPedidoPayload(BaseModel):
    nuevo_estado: str = Field(..., examples=["PROCESADO"], description="Nuevo estado logístico de la orden")

    @field_validator("nuevo_estado")
    @classmethod
    def validar_estado_maquina(cls, v: str) -> str:
        v_limpio = v.strip().upper()
        if v_limpio not in ESTADOS_VALIDOS:
            raise ValueError(f"Transición Inválida: El estado '{v}' no pertenece a la máquina de estados oficial.")
        return v_limpio

# Contrato de Salida: Actualización de auditoría confirmada
class ActualizacionEstadoResponse(BaseModel):
    pedido_id: int
    monto_total: float
    antiguo_estado: str
    nuevo_estado: str
    mensaje_auditoria: str
```

#### 🗄️ 5. Implementación del Algoritmo del Controlador (`backend/app/routers/orders.py`)

```python
from fastapi import APIRouter, Depends, HTTPException, status
from sqlalchemy.orm import Session, joinedload
from app.database import get_db
from app.models.order import Pedido, DetallePedido
from app.models.variant import TallaStock, VarianteColor
from app.schemas.order import CambiarEstadoPedidoPayload, ActualizacionEstadoResponse
from app.routers.auth import verificar_admin

router = APIRouter(prefix="/api/orders", tags=["Órdenes y Pedidos"])

@router.put(
    "/{id}/estado", 
    response_model=ActualizacionEstadoResponse,
    status_code=status.HTTP_200_OK,
    summary="Actualizar el estado logístico de un pedido y gestionar inventario (Solo Admin)"
)
def actualizar_estado_pedido(
    id: int,
    payload: CambiarEstadoPedidoPayload,
    db: Session = Depends(get_db),
    admin_actual = Depends(verificar_admin)
):
    # 1. Buscar la orden de compra junto a sus detalles hijos precargados (Evitar N+1)
    pedido = db.query(Pedido).options(
        joinedload(Pedido.items_facturados)
    ).filter(Pedido.id == id).first()

    if not pedido:
        raise HTTPException(
            status_code=status.HTTP_404_NOT_FOUND,
            detail=f"Error Logístico: El pedido con ID #{id} no existe en la base de datos."
        )

    antiguo_estado = pedido.estado_pago
    nuevo_estado_limpio = payload.nuevo_estado

    # 2. Si el pedido ya se encuentra en el estado solicitado, retornar sin ejecutar transacciones
    if antiguo_estado == nuevo_estado_limpio:
        return ActualizacionEstadoResponse(
            pedido_id=pedido.id,
            monto_total=pedido.monto_total,
            antiguo_estado=antiguo_estado,
            nuevo_estado=nuevo_estado_limpio,
            mensaje_auditoria="Sin cambios: El pedido ya ostentaba el estado solicitado."
        )

    try:
        # 3. FLUJO CRÍTICO: Si la transición es hacia CANCELADO, restituir stock físico
        if nuevo_estado_limpio == "CANCELADO":
            for detalle in pedido.items_facturados:
                # Localizar la celda exacta de inventario vinculada al producto y talla
                celda_inventario = db.query(TallaStock).join(VarianteColor).filter(
                    VarianteColor.producto_id == detalle.producto_id,
                    TallaStock.talla == detalle.talla
                ).with_for_update().first() # Bloqueo preventivo de fila en MySQL

                if celda_inventario:
                    # Devolver de forma física las unidades compradas al stock del almacén
                    celda_inventario.stock += detalle.cantidad

            msg_auditoria = "Operación Exitosa: El pedido fue anulado y las existencias fueron restituidas a almacén."
        else:
            msg_auditoria = f"Operación Exitosa: El pedido transicionó correctamente a estado '{nuevo_estado_limpio}'."

        # 4. Asentar el nuevo estado en la cabecera y confirmar la transacción de forma atómica
        pedido.estado_pago = nuevo_estado_limpio
        db.commit()
        
        return ActualizacionEstadoResponse(
            pedido_id=pedido.id,
            monto_total=pedido.monto_total,
            antiguo_estado=antiguo_estado,
            nuevo_estado=nuevo_estado_limpio,
            mensaje_auditoria=msg_auditoria
        )

    except Exception as e:
        db.rollback() # Revierte los cambios de forma síncrona si ocurre una falla física en el motor
        raise HTTPException(
            status_code=status.HTTP_500_INTERNAL_SERVER_ERROR,
            detail=f"Fallo crítico en el motor InnoDB al procesar la máquina de estados: {str(e)}"
        )
```
