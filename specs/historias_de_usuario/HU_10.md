### 📋 HU-10: Gestión de Direcciones de Despacho Urbano (Huamanga)

**Como** Cliente autenticado de SneakerHub  
**Quiero** registrar, listar y seleccionar mis direcciones de entrega detallando explícitamente el distrito, calle y referencias dentro de la provincia de Huamanga  
**Para** asegurar el correcto despacho de mis zapatillas por el equipo de delivery local y mitigar errores de enrutamiento logístico.

---

#### 📌 1. Precondiciones y Postcondiciones
* **Precondiciones:**
  1. El cliente debe estar autenticado con un token JWT vigente bajo el guardián elástico `verificar_usuario`.
  2. La tabla relacional `direcciones_entrega` debe estar debidamente creada en MySQL con una clave foránea apuntando hacia el `id` de la tabla `usuarios`.
* **Postcondiciones:**
  1. Se consolida el registro de la dirección en el motor de base de datos InnoDB.
  2. El identificador único (`direccion_id`) queda habilitado y disponible para ser enlazado de forma atómica en el JSON del ciclo transaccional de Checkout (HU-14).

---

#### 🛠️ 2. Criterios de Aceptación Técnicos Detallados
* **CA-01 (Seguridad e Identidad Perimetral):** El endpoint requiere obligatoriamente una cabecera de autorización Bearer Token válida. El sistema extraerá el `email` del token descodificado para mapear el `usuario_id` real, impidiendo que un usuario inyecte o consulte direcciones pertenecientes a otras cuentas (Aislamiento de Datos Multi-inquilino).
* **CA-02 (Validación Geográfica de Cobertura Local):** Dado el modelo logístico de SneakerHub, la cobertura de delivery se restringe estrictamente a la zona urbana y metropolitana de la provincia de Huamanga. El campo `distrito` se someterá a una validación elástica de contención de lista blanca. Solo se autorizarán los siguientes literales estrictos:
  * `"Ayacucho"` (Cercado)
  * `"San Juan Bautista"`
  * `"Carmen Alto"`
  * `"Jesús Nazareno"`
  * `"Andrés Avelino Cáceres"`
  Cualquier intento de registrar un distrito fuera del radio de cobertura (ej. Huanta o provincias colindantes) será rechazado por el backend con un código **400 Bad Request**.
* **CA-03 (Sanitización y Obligatoriedad de Referencias):** Los campos `calle_avenida` y `referencia` son campos de texto obligatorios (`NOT NULL` en MySQL). Pydantic limpiará los espacios en blanco fantasmas (`.strip()`) y exigirá una longitud mínima de 5 caracteres en la referencia (ej. *"Frente al paradero 4 de San Juan"*) para guiar al repartidor.
* **CA-04 (Umbral de Saturación de Almacenamiento):** Para mitigar ataques de denegación de servicio por llenado de tablas, un cliente individual podrá almacenar un límite máximo de **3 direcciones activas** simultáneamente en su cuenta. Si se intenta registrar una cuarta dirección, el backend arrojará un código **409 Conflict**.

#### 📊 3. Esquemas de Validación y Contratos de Datos (Pydantic)

```python
from pydantic import BaseModel, Field, field_validator

# Lista blanca de distritos autorizados en Huamanga para el delivery
DISTRITOS_COBERTURA = [
    "ayacucho", 
    "san juan bautista", 
    "carmen alto", 
    "jesús nazareno", 
    "andrés avelino cáceres"
]

class DireccionCreate(BaseModel):
    distrito: str = Field(..., examples=["San Juan Bautista"], description="Distrito urbano de entrega")
    calle_avenida: str = Field(..., min_length=4, max_length=150, description="Dirección exacta de la residencia")
    referencia: str = Field(..., min_length=5, max_length=200, description="Indicaciones detalladas para el delivery")

    @field_validator("distrito")
    @classmethod
    def validar_cobertura_distrital(cls, v: str) -> str:
        v_limpio = v.strip().lower()
        if v_limpio not in DISTRITOS_COBERTURA:
            raise ValueError(
                f"Fuera de Cobertura: El distrito '{v}' no cuenta con despacho a domicilio activo actualmente."
            )
        # Retorna el nombre formateado de forma limpia con mayúsculas iniciales
        return v_limpio.title()

class DireccionResponse(BaseModel):
    id: int
    usuario_id: int
    distrito: str
    calle_avenida: str
    referencia: str

    class Config:
        from_attributes = True
```

#### 🗄️ 5. Implementación del Algoritmo del Controlador (FastAPI + SQLAlchemy)

```python
from fastapi import APIRouter, Depends, HTTPException, status
from sqlalchemy.orm import Session
from typing import List
from app.database import get_db
from app.models.user import Usuario, DireccionEntrega  # Asumiendo el modelo relacional correspondiente
from app.schemas.user import DireccionCreate, DireccionResponse
from app.routers.auth import verificar_usuario

router = APIRouter(prefix="/api/usuarios", tags=["Usuarios"])

@router.post(
    "/direcciones", 
    status_code=status.HTTP_201_CREATED, 
    response_model=DireccionResponse,
    summary="Registrar una nueva dirección de despacho a domicilio (Solo Clientes)"
)
def agregar_direccion_despacho(
    payload: DireccionCreate, 
    db: Session = Depends(get_db),
    usuario_actual = Depends(verificar_usuario)
):
    # 1. Recuperar la cuenta del usuario mapeado por el JWT seguro
    user = db.query(Usuario).filter(Usuario.email == usuario_actual.email).first()
    
    # 2. Control de umbral: Contar cuántas direcciones posee registradas en MySQL
    conteo_direcciones = db.query(DireccionEntrega).filter(DireccionEntrega.usuario_id == user.id).count()
    if conteo_direcciones >= 3:
        raise HTTPException(
            status_code=status.HTTP_409_CONFLICT,
            detail="Umbral Saturado: Se ha alcanzado el límite máximo de 3 direcciones de entrega por cuenta."
        )

    try:
        # 3. Mapear e inyectar de forma atómica el ID del usuario autenticado
        nueva_direccion = DireccionEntrega(
            distrito=payload.distrito,
            calle_avenida=payload.calle_avenida.strip(),
            referencia=payload.referencia.strip(),
            usuario_id=user.id
        )
        
        # 4. Confirmar la transacción atómica en el motor InnoDB
        db.add(nueva_direccion)
        db.commit()
        db.refresh(nueva_direccion)
        return nueva_direccion

    except Exception as e:
        db.rollback()
        raise HTTPException(
            status_code=status.HTTP_500_INTERNAL_SERVER_ERROR,
            detail=f"Fallo crítico en el motor de persistencia al asentar la dirección urbana: {str(e)}"
        )

@router.get(
    "/direcciones", 
    response_model=List[DireccionResponse],
    status_code=status.HTTP_200_OK,
    summary="Listar todas las direcciones de entrega del cliente autenticado"
)
def listar_direcciones_usuario(
    db: Session = Depends(get_db),
    usuario_actual = Depends(verificar_usuario)
):
    # Aislar y extraer únicamente las tuplas que pertenezcan al inquilino autenticado
    user = db.query(Usuario).filter(Usuario.email == usuario_actual.email).first()
    direcciones = db.query(DireccionEntrega).filter(DireccionEntrega.usuario_id == user.id).all()
    return direcciones
```
