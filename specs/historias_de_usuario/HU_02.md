### 📋 HU-02: Registro y Catalogación Base de Calzado

**Como** Administrador de la plataforma SneakerHub Ayacucho  
**Quiero** registrar un nuevo modelo de calzado en el catálogo del sistema ingresando su ficha técnica base (nombre, precio base, porcentaje de descuento, descripción, marca y categoría)  
**Para** disponibilizar el producto en el inventario y permitir su posterior despliegue en la vitrina comercial.

---

#### 📌 1. Precondiciones y Postcondiciones
* **Precondiciones:**
  1. El usuario debe estar autenticado con un token JWT válido que contenga el rol **"admin"**.
  2. La marca (`marca_id`) y la categoría (`categoria_id`) a las que se asociará el calzado ya deben existir y estar activas en la base de datos MySQL.
* **Postcondiciones:**
  1. Se crea un nuevo registro en la tabla `productos` con el estado inicial predeterminado en **"ACTIVO"**.
  2. El identificador único (`id`) generado se guarda temporalmente en el entorno de pruebas para la ejecución de la suite secuencial en Postman.

---

#### 🛠️ 2. Criterios de Aceptación Técnicos Detallados
* **CA-01 (Validación de Relaciones Foráneas):** Para evitar fallos críticos en el motor transaccional, el backend debe realizar una consulta previa de existencia (`SELECT`) para el `marca_id` y `categoria_id` provistos. Si alguno de los identificadores no existe, se detiene la operación y se responde con un código **404 Not Found**, evitando que MySQL arroje una excepción de clave foránea de forma abrupta.
* **CA-02 (Restricciones Numéricas y Reglas de Negocio):**
  * El campo `precio_base` es obligatorio y debe ser estrictamente un valor numérico positivo mayor que cero.
  * El campo `porcentaje_descuento` es opcional, pero si se provee, debe estar restringido a un rango cerrado entre **0.0** y **100.0**. Cualquier violación de estas reglas numéricas será rechazada por Pydantic con un código **422 Unprocessable Entity**.
* **CA-03 (Protección contra Nulidad - Error 1048):** De acuerdo con el diseño del esquema físico en MySQL, las columnas `marca_id` y `categoria_id` están configuradas con la restricción `NOT NULL`. El esquema de validación debe forzar la obligatoriedad de estos campos en la petición, bloqueando valores nulos antes de interactuar con SQLAlchemy.
* **CA-04 (Control de Estado por Defecto):** El sistema asignará de forma automática el literal estricto **"ACTIVO"** en la columna `estado` de la tabla de productos durante la instanciación del objeto ORM, asegurando que el producto sea elegible para los filtros de búsqueda inmediatados.

#### 📊 3. Esquemas de Validación y Contratos de Datos (Pydantic)

```python
from pydantic import BaseModel, Field, field_validator
from typing import Optional

# Esquema de Entrada para la Creación del Producto
class ProductoCreate(BaseModel):
    nombre: str = Field(..., min_length=3, max_length=100, examples=["Nike Air Force 1"])
    precio_base: float = Field(..., description="Precio de venta base sin descuentos aplicado")
    porcentaje_descuento: Optional[float] = Field(default=0.0, description="Porcentaje promocional")
    descripcion: Optional[str] = Field(default=None, max_length=500)
    marca_id: int = Field(..., description="ID de la marca relacional (NOT NULL)")
    categoria_id: int = Field(..., description="ID de la categoría relacional (NOT NULL)")

    @field_validator("precio_base")
    @classmethod
    def validar_precio(cls, v: float) -> float:
        if v <= 0:
            raise ValueError("El precio base del calzado debe ser un monto estrictamente mayor a 0.0")
        return v

    @field_validator("porcentaje_descuento")
    @classmethod
    def validar_descuento(cls, v: float) -> float:
        if v < 0.0 or v > 100.0:
            raise ValueError("El porcentaje de descuento debe oscilar estrictamente entre 0.0 y 100.0")
        return v

# Esquema de Salida Completo (ResponseModel)
class ProductoResponse(BaseModel):
    id: int
    nombre: str
    precio_base: float
    porcentaje_descuento: float
    descripcion: Optional[str]
    marca_id: int
    categoria_id: int
    estado: str

    class Config:
        from_attributes = True
```

#### 🗄️ 5. Implementación del Algoritmo del Controlador (FastAPI + SQLAlchemy)

```python
from fastapi import APIRouter, Depends, HTTPException, status
from sqlalchemy.orm import Session
from app.database import get_db
from app.models.product import Producto, Marca, Categoria
from app.schemas.product import ProductoCreate, ProductoResponse
from app.routers.auth import verificar_admin

router = APIRouter(prefix="/api/productos", tags=["Productos"])

@router.post(
    "/", 
    status_code=status.HTTP_201_CREATED, 
    response_model=ProductoResponse,
    summary="Añadir calzado base al catálogo general (Protegido por Administrador)"
)
def crear_producto(
    payload: ProductoCreate, 
    db: Session = Depends(get_db),
    admin_actual = Depends(verificar_admin)
):
    # 1. Validar la existencia de la Marca para evitar inconsistencias relacionales
    marca = db.query(Marca).filter(Marca.id == payload.marca_id).first()
    if not marca:
        raise HTTPException(
            status_code=status.HTTP_404_NOT_FOUND,
            detail=f"Error de Integridad: La marca con ID #{payload.marca_id} no existe en MySQL."
        )

    # 2. Validar la existencia de la Categoría para prevenir registros huérfanos
    categoria = db.query(Categoria).filter(Categoria.id == payload.categoria_id).first()
    if not categoria:
        raise HTTPException(
            status_code=status.HTTP_404_NOT_FOUND,
            detail=f"Error de Integridad: La categoría con ID #{payload.categoria_id} no existe en MySQL."
        )

    try:
        # 3. Mapear el esquema de validación Pydantic hacia el modelo declarativo ORM
        nuevo_producto = Producto(
            nombre=payload.nombre,
            precio_base=payload.precio_base,
            porcentaje_descuento=payload.porcentaje_descuento,
            descripcion=payload.descripcion,
            marca_id=payload.marca_id,
            categoria_id=payload.categoria_id,
            estado="ACTIVO"  # Inyección forzada de la regla de negocio base
        )
        
        # 4. Asentar la transacción atómica en el motor de base de datos InnoDB
        db.add(nuevo_producto)
        db.commit()
        db.refresh(nuevo_producto)
        return nuevo_producto

    except Exception as e:
        db.rollback()  # Revierte los cambios de forma síncrona si ocurre una falla física
        raise HTTPException(
            status_code=status.HTTP_500_INTERNAL_SERVER_ERROR,
            detail=f"Fallo crítico en el motor relacional al asentar el calzado: {str(e)}"
        )
```
