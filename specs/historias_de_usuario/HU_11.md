### 📋 HU-11: Guardianes de Seguridad Perimetral y Control de Accesos

**Como** Desarrollador del Núcleo del Sistema / Administrador de Ciberseguridad  
**Quiero** implementar interceptores de seguridad independientes mediante el sistema de inyección de dependencias de FastAPI (`Depends`)  
**Para** centralizar el descifrado de tokens JWT, validar firmas criptográficas perimetrales y restringir el acceso a los endpoints mutadores de la API según el rol jerárquico del usuario.

---

#### 📌 1. Precondiciones y Postcondiciones
* **Precondiciones:**
  1. El cliente debe adjuntar de forma obligatoria el token digital emitido (HU-06/HU-07) dentro de las cabeceras HTTP de la solicitud utilizando el formato `Authorization: Bearer <JWT>`.
  2. Las llaves simétricas de firma (`SECRET_KEY`) y el algoritmo de cifrado (**HS256**) deben estar debidamente parametrizados en el archivo `core/config.py`.
* **Postcondiciones:**
  1. Si el token pasa la validación física, el guardián inyecta un objeto de sesión autenticado directamente en los argumentos del controlador del endpoint solicitado.
  2. Si la validación falla, el hilo de ejecución se interrumpe de manera inmediata antes de interactuar con el router o consumir recursos de red de la base de datos MySQL.

---

#### 🛠️ 2. Criterios de Aceptación Técnicos Detallados
* **CA-01 (Auditoría Estructural de Cabecera OAuth2):** El sistema implementará la estrategia `OAuth2PasswordBearer` apuntando al endpoint `/api/auth/login`. El backend debe interceptar la cabecera HTTP y corroborar la presencia del prefijo estricto `Bearer `. Si la cabecera se encuentra ausente o mal formateada, se expulsa la solicitud arrojando de forma automática un código **401 Unauthorized**.
* **CA-02 (Validación de Integridad Criptográfica):** Utilizando la librería `python-jose`, el interceptor descodificará el payload del token. Si el token está alterado (colisión de firmas), corrupto o su marca de tiempo interna ha expirado (`exp`), el backend lanzará una excepción controlada emitiendo un código **401 Unauthorized** con el detalle genérico: `"Token inválido o expirado. Inicie sesión nuevamente."`
* **CA-03 (Guardián Elástico de Usuario General - `verificar_usuario`):** Esta dependencia valida la existencia real de la cuenta. Extrae la propiedad `sub` (correo electrónico) del token descodificado y realiza un barrido veloz en la tabla `usuarios`. Si la cuenta existe, retorna el modelo del usuario. Se utiliza para operaciones transaccionales comunes del cliente (Carrito, Direcciones, Pedidos).
* **CA-04 (Guardián Restrictivo Jerárquico - `verificar_admin`):** Diseñado para la protección absoluta del catálogo e inventarios (HU-01, HU-02, HU-08, HU-15). Este interceptor hereda el flujo de descodificación y evalúa estrictamente que la propiedad interna `rol` del payload sea textualmente idéntica al literal **"admin"**. Ante cualquier desviación (como un rol cliente intentando inyectar stock), el sistema anula la operación emitiendo un código **403 Forbidden** (*Acceso denegado. Privilegios insuficientes.*).

#### 📊 3. Esquemas de Validación y Contratos de Datos (Pydantic)

```python
from pydantic import BaseModel, Field, EmailStr
from typing import Optional

# Esquema interno para el mapeo del contenido del JWT descodificado
class TokenDataPayload(BaseModel):
    email: Optional[EmailStr] = Field(default=None, alias="sub", description="Identidad del usuario (Subject)")
    rol: Optional[str] = Field(default=None, description="Rol jerárquico asignado en la base de datos")
```

#### 🗄️ 5. Implementación del Algoritmo de los Guardianes (`backend/app/routers/auth.py`)

```python
from fastapi import Depends, HTTPException, status
from fastapi.security import OAuth2PasswordBearer
from jose import JWTError, jwt
from sqlalchemy.orm import Session
from app.database import get_db
from app.core.config import SECRET_KEY, ALGORITHM
from app.models.user import Usuario
from app.schemas.user import TokenDataPayload

# Configuración del extractor automático de cabeceras estándar HTTP
oauth2_scheme = OAuth2PasswordBearer(tokenUrl="/api/auth/login")

def verificar_usuario(token: str = Depends(oauth2_scheme), db: Session = Depends(get_db)) -> Usuario:
    credentials_exception = HTTPException(
        status_code=status.HTTP_401_UNAUTHORIZED,
        detail="Token inválido o expirado. Inicie sesión nuevamente.",
        headers={"WWW-Authenticate": "Bearer"},
    )
    try:
        # 1. Descodificar el token utilizando la llave simétrica del backend
        payload = jwt.decode(token, SECRET_KEY, algorithms=[ALGORITHM])
        email: str = payload.get("sub")
        rol: str = payload.get("rol")
        
        if email is None or rol is None:
            raise credentials_exception
            
        token_data = TokenDataPayload(sub=email, rol=rol)
        
    except JWTError:
        raise credentials_exception

    # 2. Corroborar existencia del usuario en la base de datos MySQL
    usuario = db.query(Usuario).filter(Usuario.email == token_data.email).first()
    if usuario is None:
        raise credentials_exception
        
    return usuario  # Retorna la entidad ORM hidratada al controlador

def verificar_admin(usuario_actual: Usuario = Depends(verificar_usuario)) -> Usuario:
    # 3. Evaluar de forma estricta la claim del rol jerárquico
    if usuario_actual.rol != "admin":
        raise HTTPException(
            status_code=status.HTTP_403_FORBIDDEN,
            detail="Acceso Denegado: Esta operación requiere privilegios elevados de Administrador."
        )
    return usuario_actual
```
