### 📋 HU-12: Motor de Descuentos Dinámicos y Aplicación de Reglas Promocionales

**Como** Administrador de la plataforma SneakerHub Ayacucho  
**Quiero** gestionar y aplicar porcentajes de descuento promocionales a modelos específicos de calzado directamente en el catálogo  
**Para** incentivar las ventas mediante campañas comerciales elásticas, garantizando que el cálculo de precios netos se compute con precisión en el servidor y se refleje en tiempo real en la vitrina web.

---

#### 📌 1. Precondiciones y Postcondiciones
* **Precondiciones:**
  1. El usuario que ejecuta la mutación del descuento debe poseer un token JWT válido con el claim `"rol": "admin"`.
  2. El calzado de destino (`producto_id`) al que se le aplicará la regla promocional debe existir activamente en la tabla `productos` de MySQL.
* **Postcondiciones:**
  1. Se actualiza de forma persistente la columna `porcentaje_descuento` en la fila correspondiente del producto en MySQL.
  2. Todas las consultas subsecuentes del cliente frontend (Vitrina HU-03, Búsqueda HU-04 y Carrito HU-09) renderizan el nuevo valor computado inmediatamente.

---

#### 🛠️ 2. Criterios de Aceptación Técnicos Detallados
* **CA-01 (Seguridad de Campañas):** El endpoint de actualización y asignación de descuentos de precios está blindado mediante el interceptor perimetral `@verificar_admin`. Intentos de consumo por parte de clientes comunes o usuarios anónimos retornan un código **403 Forbidden**.
* **CA-02 (Rango Matemático de Descuento Promocional):** El valor inyectado en el campo `porcentaje_descuento` debe ser un tipo numérico decimal (`float`) restringido estrictamente a un rango acotado cerrado entre 0.0 y 100.0 ($0.0 \le porcentaje\_descuento \le 100.0$). Un descuento de 0.0 indica la anulación completa de cualquier promoción previa (precio regular). Violaciones de rango provocan una excepción estructural **422 Unprocessable Entity**.
* **CA-03 (Ecuación Invariante de Precio Neto en Servidor):** Por motivos de seguridad financiera y auditoría transaccional, el cálculo final del subtotal descontado jamás se delega al frontend. El backend computará el precio final neto de venta aplicando de forma determinista la siguiente fórmula algebraica:

  Precio Neto = Precio Base * ( 1 - ( Porcentaje Descuento / 100 ) )

  El resultado matemático resultante se someterá de forma obligatoria a una función de truncado/redondeo simétrico a dos dígitos decimales exactos (`round(valor, 2)`) antes de ser despachado en el JSON de respuesta o almacenado en los detalles de compra.

#### 📊 3. Esquemas de Validación y Contratos de Datos (Pydantic)

```python
from pydantic import BaseModel, Field, field_validator

# Esquema de Entrada: Payload para inyectar o modificar la regla promocional
class AplicarDescuentoPayload(BaseModel):
    porcentaje_descuento: float = Field(
        ..., 
        description="Porcentaje de rebaja comercial a aplicar sobre el precio base"
    )

    @field_validator("porcentaje_descuento")
    @classmethod
    def validar_limites_promocion(cls, v: float) -> float:
        if v < 0.0 or v > 100.0:
            raise ValueError("Error de Campaña: El porcentaje de descuento promocional debe oscilar entre 0.0 y 100.0")
        return v

# Esquema de Respuesta: Confirmación del nuevo estado financiero del calzado
class ProductoDescuentoResponse(BaseModel):
    id: int
    nombre: str
    precio_base: float
    porcentaje_descuento: float
    precio_neto_calculado: float = Field(..., description="Precio final de venta computado por el backend")
    estado: str

    class Config:
        from_attributes = True
```

#### 🗄️ 5. Implementación del Algoritmo del Controlador (FastAPI + SQLAlchemy)

```python
from fastapi import APIRouter, Depends, HTTPException, status
from sqlalchemy.orm import Session
from app.database import get_db
from app.models.product import Producto
from app.schemas.product import AplicarDescuentoPayload, ProductoDescuentoResponse
from app.routers.auth import verificar_admin

router = APIRouter(prefix="/api/productos", tags=["Productos"])

@router.put(
    "/{id}/descuento", 
    response_model=ProductoDescuentoResponse,
    status_code=status.HTTP_200_OK,
    summary="Asignar o modificar el porcentaje de descuento de un calzado (Solo Admin)"
)
def aplicar_descuento_catalogo(
    id: int,
    payload: AplicarDescuentoPayload,
    db: Session = Depends(get_db),
    admin_actual = Depends(verificar_admin)
):
    # 1. Buscar la entidad del calzado por ID en la base de datos MySQL
    producto = db.query(Producto).filter(Producto.id == id).first()
    if not producto:
        raise HTTPException(
            status_code=status.HTTP_404_NOT_FOUND,
            detail=f"Error Promocional: El calzado con ID #{id} no existe en el catálogo."
        )

    try:
        # 2. Mutar de forma persistente el porcentaje de descuento en el modelo ORM
        producto.porcentaje_descuento = payload.porcentaje_descuento
        db.commit()
        db.refresh(producto)

        # 3. Calcular la invariante de precio neto aplicando redondeo a 2 decimales
        descuento_factor = producto.porcentaje_descuento / 100.0
        precio_neto = producto.precio_base * (1.0 - descuento_factor)
        precio_neto_redondeado = round(precio_neto, 2)

        # 4. Construir y despachar el contrato de respuesta estructurado
        return ProductoDescuentoResponse(
            id=producto.id,
            nombre=producto.nombre,
            precio_base=producto.precio_base,
            porcentaje_descuento=producto.porcentaje_descuento,
            precio_neto_calculado=precio_neto_redondeado,
            estado=producto.estado
        )

    except Exception as e:
        db.rollback()
        raise HTTPException(
            status_code=status.HTTP_500_INTERNAL_SERVER_ERROR,
            detail=f"Fallo crítico transaccional al asentar la regla de descuento: {str(e)}"
        )
```
