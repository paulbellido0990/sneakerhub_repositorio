## 🔐 MÓDULO B: CONTROL PERIMETRAL, SEGURIDAD Y USUARIOS

### 📋 HU-06: Registro Público de Clientes con Validación Estricta

**Como** Nuevo cliente residente de la región de Ayacucho  
**Quiero** auto-registrar una cuenta en la plataforma ingresando mis datos personales (nombre, correo electrónico, contraseña y teléfono celular)  
**Para** obtener acceso seguro al ecosistema, gestionar un carrito de compras persistente y ejecutar órdenes transaccionales de calzado.

---

#### 📌 1. Precondiciones y Postcondiciones
* **Precondiciones:**
  1. El servidor de base de datos MySQL debe estar activo y la tabla de usuarios debe contar con un índice único configurado en la columna `email`.
  2. El cliente frontend debe enviar la petición asíncrona hacia el enrutador de autenticación correspondiente.
* **Postcondiciones:**
  1. Se inserta una nueva fila en la tabla de usuarios con el rol estructural inmutable de **"cliente"**.
  2. La contraseña es procesada criptográficamente antes del almacenamiento masivo.
  3. El sistema autogenera y retorna un token JSON Web Token (JWT) firmado de forma síncrona para iniciar de inmediato la sesión del usuario.

---

#### 🛠️ 2. Criterios de Aceptación Técnicos Detallados
* **CA-01 (Validación de Unicidad de Identidad):** Antes de proceder con la inserción del nuevo registro, el backend debe realizar una consulta indexada para verificar la existencia previa del correo electrónico (`email`) en la base de datos. Ante una coincidencia exacta, se detiene el flujo y se arroja un código **400 Bad Request**, previniendo la duplicación de cuentas.
* **CA-02 (Validación por Expresiones Regulares del Teléfono Celular):** Para asegurar la correcta comunicación en entregas de delivery dentro de Huamanga, el campo celular se somete a una validación estricta por expresiones regulares mediante el patrón regex: `r"^\d{9}$"`. El payload debe contener exactamente 9 dígitos de naturaleza numérica entera. Cualquier inclusión de caracteres especiales, letras o longitudes distintas será bloqueada por Pydantic arrojando un código **422 Unprocessable Entity**.
* **CA-03 (Seguridad Criptográfica y Salado de Contraseñas):** Está estrictamente prohibido el almacenamiento de credenciales en formato de texto plano en cualquier capa del sistema. El backend debe interceptar la contraseña provista y aplicar un algoritmo de derivación de claves robusto mediante la librería `bcrypt`, inyectando un factor de salado elástico antes de asentar el valor final en la columna `contrasena_hash` de MySQL.
* **CA-04 (Blindaje de Inyección de Roles):** Para neutralizar vulnerabilidades de escalada de privilegios, el esquema de entrada de datos omite cualquier propiedad relacionada con el rol. El backend asignará de forma mandataria el literal **"cliente"** en caliente durante el mapeo de la entidad ORM. El rol "admin" solo puede ser asignado mediante scripts manuales de base de datos (como una siembra directa).

#### 📊 3. Esquemas de Validación y Contratos de Datos (Pydantic)

```python
from pydantic import BaseModel, Field, EmailStr, field_validator
import re

# Esquema estricto de entrada para auto-registro público
class UsuarioRegister(BaseModel):
    nombre: str = Field(..., min_length=3, max_length=60, examples=["Paul Llallahui"])
    email: EmailStr = Field(..., description="Correo electrónico único que servirá como credencial")
    password: str = Field(..., min_length=6, max_length=30, description="Contraseña segura de acceso")
    telefono: str = Field(..., description="Número celular de 9 dígitos numéricos obligatorios")

    @field_validator("telefono")
    @classmethod
    def validar_telefono_regex(cls, v: str) -> str:
        # Sanitizar quitando espacios accidentales
        v_limpio = v.strip()
        patron = r"^\d{9}$"
        if not re.match(patron, v_limpio):
            raise ValueError("Formato Inválido: El teléfono celular debe constar de exactamente 9 dígitos numéricos.")
        return v_limpio

# Contrato de salida que expone el token de acceso inmediato
class TokenResponse(BaseModel):
    access_token: str = Field(..., description="Firma criptográfica JWT emitida para la sesión")
    token_type: str = Field(default="bearer", description="Estrategia de autorización HTTP")
```

#### 🗄️ 5. Implementación del Algoritmo del Controlador (FastAPI + SQLAlchemy)

```python
from fastapi import APIRouter, Depends, HTTPException, status
from sqlalchemy.orm import Session
from app.database import get_db
from app.models.user import Usuario
from app.schemas.user import UsuarioRegister, TokenResponse
from app.core.security import registrar_hash_contrasena, crear_token_acceso

router = APIRouter(prefix="/api/auth", tags=["Autenticación"])

@router.post(
    "/register", 
    status_code=status.HTTP_201_CREATED, 
    response_model=TokenResponse,
    summary="Auto-registro público de nuevos clientes en la plataforma"
)
def registrar_cliente(
    payload: UsuarioRegister, 
    db: Session = Depends(get_db)
):
    # 1. Control perimetral de duplicados en la base de datos MySQL
    correo_sanitizado = payload.email.strip().lower()
    usuario_existente = db.query(Usuario).filter(Usuario.email == correo_sanitizado).first()
    if usuario_existente:
        raise HTTPException(
            status_code=status.HTTP_400_BAD_REQUEST,
            detail="Error de Registro: El correo electrónico ya se encuentra vinculado a una cuenta activa."
        )

    try:
        # 2. Encriptación criptográfica de la credencial de acceso (Bcrypt)
        hash_seguro = registrar_hash_contrasena(payload.password)
        
        # 3. Mapear objeto ORM inyectando el rol "cliente" de forma forzada y segura
        nuevo_cliente = Usuario(
            nombre=payload.nombre.strip(),
            email=correo_sanitizado,
            contrasena_hash=hash_seguro,
            telefono=payload.telefono,
            rol="cliente"  # Regla de negocio inalterable desde el exterior
        )
        
        # 4. Asentar los cambios de manera persistente mediante confirmación transaccional
        db.add(nuevo_cliente)
        db.commit()
        db.refresh(nuevo_cliente)
        
        # 5. Generar token JWT de acceso inmediato con las claims de identidad correspondientes
        payload_token = {"sub": nuevo_cliente.email, "rol": nuevo_cliente.rol}
        token_jwt = crear_token_acceso(data=payload_token)
        
        return TokenResponse(access_token=token_jwt, token_type="bearer")

    except Exception as e:
        db.rollback()
        raise HTTPException(
            status_code=status.HTTP_500_INTERNAL_SERVER_ERROR,
            detail=f"Fallo crítico en el subsistema de seguridad al asentar el perfil: {str(e)}"
        )
```
