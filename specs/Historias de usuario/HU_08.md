### 📋 HU-08: Control de Almacén y Matriz de Stock Inicial (Admin)

**Como** Administrador de almacén de SneakerHub Ayacucho  
**Quiero** asignar existencias físicas iniciales a un calzado del catálogo vinculando la cantidad exacta de unidades a una combinación de producto y talla  
**Para** registrar la carga inicial de mercancía recibida en los almacenes, inicializar las matrices de control de inventario y habilitar el stock para la comercialización web.

---

#### 📌 1. Precondiciones y Postcondiciones
* **Precondiciones:**
  1. El usuario debe estar autenticado mediante un token JWT con el rol oficial de **"admin"**.
  2. El calzado base (`producto_id`) al que se le inyectarán existencias físicas debe estar previamente creado en la tabla `productos`.
* **Postcondiciones:**
  1. Se consolida un nuevo registro persistente en la tabla relacional `tallas_stock` de MySQL.
  2. El stock asignado queda inmediatamente disponible en el catálogo para ser visualizado e indexado en las consultas del motor de búsqueda (HU-04).

---

#### 🛠️ 2. Criterios de Aceptación Técnicos Detallados
* **CA-01 (Seguridad Perimetral Logística):** Al tratarse de una operación que altera directamente los activos físicos y contables del e-commerce, el controlador está blindado bajo el guardián de alta prioridad `@verificar_admin`. Intentos de acceso sin token válido devuelven **401 Unauthorized** y usuarios con rol cliente reciben **403 Forbidden**.
* **CA-02 (Validación de Existencia de Entidad Base):** El algoritmo del backend debe interceptar el `producto_id` provisto en el payload de entrada y realizar una verificación de presencia asíncrona en la base de datos. Si el producto no es localizado, el hilo transaccional se interrumpe inmediatamente emitiendo un código de estado **404 Not Found**.
* **CA-03 (Manejo Elástico de Variantes y Fallback "Estándar"):** Para flexibilizar el flujo de inventario, el sistema evalúa si el producto ya cuenta con al menos una fila registrada en la tabla intermedia `variantes_color`. En caso de encontrarse vacía (es decir, si es la primera carga física de mercancía), el backend autogenerará en caliente una variante comodín con el atributo de color seteado como **"Estándar"** para proveer el anclaje de clave foránea indispensable para MySQL.
* **CA-04 (Restricción de Volumen de Carga):** El volumen numérico asignado en el campo `stock_inicial` debe ser obligatoriamente un número entero positivo mayor a cero ($stock\_inicial > 0$). Pydantic auditará este tipo de dato, rechazando caracteres alfabéticos, decimales o valores negativos mediante un código **422 Unprocessable Entity**.

#### 📊 3. Esquemas de Validación y Contratos de Datos (Pydantic)

```python
from pydantic import BaseModel, Field, field_validator

# Esquema de Entrada para la carga física de almacén
class StockInicialCreate(BaseModel):
    producto_id: int = Field(..., description="ID del calzado base registrado en MySQL")
    talla: str = Field(..., min_length=1, max_length=10, examples=["42"])
    stock_inicial: int = Field(..., description="Cantidad de pares físicos ingresando a almacén")

    @field_validator("stock_inicial")
    @classmethod
    def verificar_volumen_positivo(cls, v: int) -> int:
        if v <= 0:
            raise ValueError("Error de Almacén: El stock inicial debe ser un número entero estrictamente mayor a 0.")
        return v
        
    @field_validator("talla")
    @classmethod
    def sanitizar_talla(cls, v: str) -> str:
        return v.strip()

# Esquema de Salida que confirma el asentamiento físico del lote
class StockInicialResponse(BaseModel):
    id: int = Field(..., description="ID autoincremental de la celda de inventario")
    variante_color_id: int = Field(..., description="ID de la variante cromática asociada")
    talla: str
    stock: int = Field(..., description="Stock consolidado final en la base de datos")

    class Config:
        from_attributes = True
```

#### 🗄️ 5. Implementación del Algoritmo del Controlador (FastAPI + SQLAlchemy)

```python
from fastapi import APIRouter, Depends, HTTPException, status
from sqlalchemy.orm import Session
from app.database import get_db
from app.models.product import Producto
from app.models.variant import VarianteColor, TallaStock
from app.schemas.variant import StockInicialCreate, StockInicialResponse
from app.routers.auth import verificar_admin

router = APIRouter(prefix="/api/productos", tags=["Productos"])

@router.post(
    "/variants/stock", 
    status_code=status.HTTP_201_CREATED, 
    response_model=StockInicialResponse,
    summary="Asignar e inicializar stock físico por talla para un calzado (Solo Admin)"
)
def inicializar_stock_almacen(
    payload: StockInicialCreate, 
    db: Session = Depends(get_db),
    admin_actual = Depends(verificar_admin)
):
    # 1. Validar la existencia real del producto base en MySQL
    producto = db.query(Producto).filter(Producto.id == payload.producto_id).first()
    if not producto:
        raise HTTPException(
            status_code=status.HTTP_404_NOT_FOUND,
            detail=f"Fallo de Inventario: El calzado base con ID #{payload.producto_id} no existe."
        )

    try:
        # 2. Evaluar si el producto posee una variante cromática activa
        variante = db.query(VarianteColor).filter(VarianteColor.producto_id == payload.producto_id).first()
        
        # 3. Flujo elástico alternativo: Si no hay variante, autogenerar el fallback 'Estándar'
        if not variante:
            variante = VarianteColor(
                color="Estándar",
                producto_id=payload.producto_id
            )
            db.add(variante)
            db.commit()
            db.refresh(variante) # Recuperamos el ID autoincremental de la nueva variante

        # 4. Control de Duplicados en Celda: Verificar si ya existe esa talla para la variante
        celda_existente = db.query(TallaStock).filter(
            TallaStock.variante_color_id == variante.id,
            TallaStock.talla == payload.talla
        ).first()

        if celda_existente:
            # Si ya existe, acumulamos de forma limpia el nuevo lote al stock actual
            celda_existente.stock += payload.stock_inicial
            db.commit()
            db.refresh(celda_existente)
            return celda_existente

        # 5. Si la celda es nueva, instanciamos el registro físico en la matriz TallaStock
        nueva_celda_stock = TallaStock(
            talla=payload.talla,
            stock=payload.stock_inicial,
            variante_color_id=variante.id
        )
        
        db.add(nueva_celda_stock)
        db.commit()
        db.refresh(nueva_celda_stock)
        return nueva_celda_stock

    except Exception as e:
        db.rollback()
        raise HTTPException(
            status_code=status.HTTP_500_INTERNAL_SERVER_ERROR,
            detail=f"Fallo crítico transaccional en el motor de almacén InnoDB: {str(e)}"
        )
```
