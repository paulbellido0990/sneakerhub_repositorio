## 📦 MÓDULO A: GESTIÓN DE CATÁLOGO Y ESTRUCTURA COMERCIAL

### 📋 HU-01: Gestión de Marcas y Categorías (Admin)

**Como** Administrador de la plataforma SneakerHub  
**Quiero** realizar operaciones completas de creación, lectura, actualización y borrado (CRUD) sobre las tablas maestras de Marcas y Categorías  
**Para** mantener la integridad relacional del catálogo de zapatillas, estructurar la navegación comercial del frontend y evitar datos redundantes en MySQL.

---

#### 📌 1. Precondiciones y Postcondiciones
* **Precondiciones:**
  1. El usuario debe haber iniciado sesión en el sistema y poseer un token JWT válido.
  2. El payload del token JWT debe contener explícitamente el claim `"rol": "admin"`.
  3. El servidor de MySQL debe estar en línea con las tablas `marcas` y `categorias` correctamente indexadas.
* **Postcondiciones:**
  1. Al registrar o modificar una marca/categoría, los cambios se asientan de forma persistente e inmediata mediante un `commit` transaccional.
  2. Los nuevos identificadores (`id`) autoincrementales quedan disponibles para indexar nuevos productos.

---

#### 🛠️ 2. Criterios de Aceptación Técnicos Detallados
* **CA-01 (Seguridad Perimetral y Control de Acceso):** Los endpoints mutadores (`POST`, `PUT`, `DELETE`) deben rechazar cualquier solicitud que carezca de un Bearer Token válido en la cabecera HTTP. Ante un token ausente o corrupto, responde con **`401 Unauthorized`**. Si el token pertenece a un rol `"cliente"`, el backend aborta la petición y responde con **`403 Forbidden`**.
* **CA-02 (Validación Estricta de Unicidad):** El campo `nombre` en ambas tablas posee una restricción de índice único a nivel de motor de base de datos. El backend debe interceptar esto antes de la inserción usando comparaciones insensibles a mayúsculas/minúsculas (`.ilike()`). Si hay colisión de datos, se ejecuta un `rollback` automático y se retorna un **`400 Bad Request`**.
* **CA-03 (Sanitización de Datos de Entrada):** Todo nombre enviado debe ser purificado eliminando espacios en blanco innecesarios al inicio y al final (`.strip()`) antes de evaluar las validaciones de longitud mínima.
* **CA-04 (Restricción de Integridad Referencial - Borrado Seguro):** No se permite el borrado físico (`HARD DELETE`) de una Marca o Categoría si la columna `marca_id` o `categoria_id` de la tabla `productos` está apuntando a dicho registro. El motor InnoDB de MySQL bloqueará la acción arrojando un fallo de clave foránea, el cual debe ser capturado por FastAPI para responder un **`409 Conflict`**.

#### 📊 3. Esquemas de Validación y Contratos de Datos (Pydantic)

```python
from pydantic import BaseModel, Field
from datetime import datetime
from typing import Optional

# Esquemas de Entrada (Petición)
class EstructuraBase(BaseModel):
    nombre: str = Field(
        ..., 
        min_length=2, 
        max_length=50, 
        examples=["Nike", "Urbano"],
        description="Nombre único de la marca o categoría comercial"
    )

class MarcaCreate(EstructuraBase):
    pass

class CategoriaCreate(EstructuraBase):
    pass

# Esquemas de Salida (Respuesta del Servidor)
class EstructuraResponse(BaseModel):
    id: int = Field(..., description="Identificador único autoincremental en MySQL")
    nombre: str
    fecha_creacion: Optional[datetime] = Field(default_factory=datetime.utcnow)

    class Config:
        from_attributes = True # Habilita el mapeo directo desde objetos ORM de SQLAlchemy
```

#### 🗄️ 5. Implementación del Algoritmo del Controlador (FastAPI + SQLAlchemy)

```python
from fastapi import APIRouter, Depends, HTTPException, status
from sqlalchemy.orm import Session
from app.database import get_db
from app.models.product import Marca
from app.schemas.product import MarcaCreate, EstructuraResponse
from app.routers.auth import verificar_admin

router = APIRouter(prefix="/api/productos", tags=["Productos"])

@router.post(
    "/marcas", 
    status_code=status.HTTP_201_CREATED, 
    response_model=EstructuraResponse,
    summary="Registrar una nueva marca en el sistema (Solo Administradores)"
)
def registrar_marca(
    payload: MarcaCreate, 
    db: Session = Depends(get_db), 
    admin_actual = Depends(verificar_admin)
):
    # 1. Sanitizar datos limpiando espacios fantasmas
    nombre_limpio = payload.nombre.strip()
    
    # 2. Control de duplicados elástico insensible a mayúsculas
    marca_existente = db.query(Marca).filter(Marca.nombre.ilike(nombre_limpio)).first()
    if marca_existente:
        raise HTTPException(
            status_code=status.HTTP_400_BAD_REQUEST,
            detail=f"Integridad Comercial: La marca '{nombre_limpio}' ya existe en el sistema."
        )
    
    try:
        # 3. Construir modelo ORM y asentar en MySQL
        nueva_marca = Marca(nombre=nombre_limpio)
        db.add(nueva_marca)
        db.commit()
        db.refresh(nueva_marca) # Hidrata el ID autoincremental generado por MySQL
        return nueva_marca
        
    except Exception as e:
        db.rollback() # Revierte la transacción ante cualquier anomalía de red o motor
        raise HTTPException(
            status_code=status.HTTP_500_INTERNAL_SERVER_ERROR,
            detail=f"Fallo crítico de persistencia al guardar la marca: {str(e)}"
        )
```
